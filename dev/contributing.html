Contributing#

Contributions are welcome. CONTRIBUTING.md explains how to set up a development environment, run the checks, what each CI workflow does, and how a pull request and a release go. AGENTS.md is the short guide for contributors and coding agents: the rules the code keeps, the commands, and the gotchas. This page holds the longer notes it points to: the module layout, the inversion package and its component cache, how the docs are written and generated, and a note on the tests.

This project is developed with the help of AI coding agents, directed and reviewed by the maintainer, who owns the design and the science. If you contribute with an agent, AGENTS.md at the repository root is the orientation file it should read.

slv.__init__ is intentionally small (just get_data_dir and the version metadata). The subpackages are the API surface:

from slv.domain import BBOX, EXTENT, XMIN, XMAX, YMIN, YMAX
from slv.basemap import SaltLake
from slv.measurements import aggregate_obs, load_concentrations, get_site_coordinates
from slv.emissions import plot_point_sources

The base install is enough for domain, basemap, measurements and emissions; the inversion extra unlocks slv.inversion (it depends on fips[viz] and pystilt).

The inversion package#

This section holds everything about the inversion package’s layout, exports, cache and pipeline internals, in one place.

src/slv/inversion/
  __init__.py      re-exports InversionConfig, build_problem, run, Sweep,
                   run_sweep_job, SweepResults
  config.py        InversionConfig — pydantic-ish config for an inversion;
                   DEFAULT_STILT_PROJECT + stilt_project_dir() ($SLV_STILT_DIR);
                   state_grid (stilt Grid, domain snapped outward to whole cells) is
                   the one definition of the flux cells, `grid` takes its axes
  pipelines.py     the pipeline proper, as functions of the config: get_obs / get_prior /
                   get_constant (pandas Series) / get_flux_jacobian (a fips Operator,
                   receptor rows) / get_prior_error (cached components),
                   filter_state_space, get_bias (fips.offset_block), obs_sites;
                   build_problem(config) -> fips.Problem (labels rounded to
                   LABEL_DECIMALS, the Jacobian placed on the obs, daily means by
                   fips.aggregate.mean); run(config, problem=None) -> fips.Posterior
  cache.py         component cache: DEFAULT_COMPONENT_DEPS sets, _component_hash,
                   _pkg_rev / _version_tag, fips_cache (pickles what the function returns)
  mdm.py           get_modeldata_mismatch (cached; sum of covariance models on the obs),
                   multiplicative_scale, per_obs_std (subhour)
  coverage.py      check_state_cells, covered_state (the Jacobian coverage filter's
                   cells; the problem of them is problem.restrict(keep))
  report.py        domain totals (calculate_total_flux, fluxes_as_inventory), summarize
                   (prints), desroziers_diagnostic, plot_inputs/results/diagnostics
  priors.py        prior flux construction
  covariances.py   covariance models: build_prior_error (Kronecker factors),
                   build_mdm_error (one MDM component)
  data.py          inversion-time data loading
  background.py    inversion background model
  viz.py           inversion-specific plotting; plot_flux_maps (the
                   prior/posterior/difference maps)
  sweep.py         Sweep / run_sweep_job / SweepResults — hyperparam sweeps

The component cache#

@fips_cache (inversion/cache.py) writes each component to {cache_dir}/.fips/{version_tag}/{component}/{hash}.pkl. version_tag is the git describe rev of the editable fips and pystilt checkouts (_version_tag and _pkg_rev), so committing or editing those packages busts the cache automatically, with no reinstall. A copy under site-packages (the uv .venv, which sits inside the slv repo, or the pixi env) uses its metadata version instead, written as the release’s tag (v0.1.0b9): git describe there would answer with slv’s rev, and a release names the same folder installed or checked out.

build_problem raises when the prior’s cells and the Jacobian’s columns differ (stale caches after a grid change; coverage.check_state_cells).

Components other than the Jacobian also hash the release of lair and uataq (COMPONENT_PACKAGES, _release: an editable checkout’s static pyproject version or latest git tag, else the installed version). A release, not an edit, rebuilds the obs, prior, MDM and constant.

Input files are keyed by what is in them, never by path alone: mobile_obs_key and background_kwargs_key (the CT-STILT csv_path) are path + size + mtime (config._file_key), and the Jacobian and MDM pass fips_cache(..., key=...) the footprints they use (_footprint_key: per project, the footprint settings folder and how many selected receptors have a footprint), so it lists the project on every cached run.

The cache key does not hold slv’s own rev (so a change to slv’s component-building logic is forced with config.cache_overwrite, or re-keyed by bumping its number in DEFAULT_COMPONENT_REVISIONS, as AGENTS.md says). When you cut a version, reinstall the editable packages (uv sync or pip install -e) so that importlib.metadata matches the source: this does not affect the cache key but keeps pip show and other version consumers honest.

Notes on the pipeline#

  • Mobile (TRAX) obs are keyed by PYSTILT location_id, not site. Anything keyed by site must resolve through pipelines.obs_sites (receptor -> the single mobile site in config.sites); the MDM and the bias Jacobian do. The rolling background uses stationary sites only (split_sites; override with background_kwargs={"background_sites": [...]}) and each obs takes its hour’s value; get_slv_subhour_std skips mobile sites.

  • get_flux_jacobian is the cached (forward_operator) flux Jacobian; the bias block (get_bias, one offset per group that has obs) is rebuilt every run and not cached. A receptor with an empty footprint is a row of zeros; the obs of a receptor with no footprint are dropped in build_problem.

  • InversionConfig.__post_init__ validates flux_freq, bias_grouping, background, prior, mdm_config and domain; setting any field drops the cached derived values.

  • InversionConfig.mdm_config keys must be names in DEFAULT_MDM_CONFIG (part, instr, aggr, subhour, bg, transport); get_mdm_comp_configs raises on anything else. Retired keys (transport_pbl, transport_wind) used to be ignored silently, leaving the MDM cache hash unchanged.

  • get_slv_observations loads the TRAX route points only when a mobile site is in sites; tower-only runs need no TRAX data.

  • InversionConfig.stilt_project defaults to SLV_STILT_DIR if set, else DEFAULT_STILT_PROJECT (the CHPC paper-1 PYSTILT project), so the config stays usable without the environment variable.

  • load_epa_prior reads EPA’s express product either way (EPAv2(express=True, scale_by_month=not express)), so the monthly default and paper 1’s annual express=True hold the same emissions (27 sectors including post-meter, 2012-2020); it relies on lair >= v2026.12.6 holding sectors without monthly scale factors at their annual rate.

Writing the docs#

Examples run when the docs build, so they show real output, and the build fails when one breaks.

A figure in a docstring: put a .. plot:: directive in the Examples section. Its code runs (doctest >>> lines work), and the figure appears under it.

Examples
--------
.. plot::

   >>> import matplotlib.pyplot as plt
   >>> _ = plt.plot([0, 1, 2], [0, 1, 4])

Code in an .rst page: a .. ipython:: python block runs, and shows each line with its output, as in an IPython session. Changing a .. code-block:: python to .. ipython:: python is enough to make it run. For a figure, put @savefig name.png on the line above the plotting call.

.. ipython:: python

   import matplotlib.pyplot as plt
   import slv

   slv.__version__

   @savefig squares.png width=5in
   plt.plot([0, 1, 2], [0, 1, 4]);

A block that raises or warns fails the build; :okexcept: or :okwarning: under the directive allows one that is meant to. All .rst pages share one session, so each page imports and defines what it uses.

When they run: just build-docs runs everything, as CI does; just docs-serve reruns a page’s blocks whenever that page is rebuilt.

Notebooks, and code cells in Markdown pages, are off in this project. copier update --data docs_notebooks=true turns them on; it adds myst-nb, and Jupyter with it, to the dev tools.

The API reference has a page for each class, with tables of its attributes and methods, and a page for each member; a subclass lists what it defines and links to what it inherits (docs/_templates/autosummary/ and docs/_ext/api_pages.py, from python-template). The extension also drops from a class docstring the Methods section and the Attributes entries that the tables list. A property or attribute’s page is where its See Also and Examples go, as in pandas: give each public one a docstring that says what it is, and add See Also or Examples where they help. One with no docstring shows an empty row.

Notes on the tests#

  • The pixi env pins the no-MPI ESMF build (build = "nompi*"): with the MPICH build, the MPI start-up on import xesmf sometimes killed the whole pytest process (exit 143, no traceback), about half the runs until 2026-10-05.
