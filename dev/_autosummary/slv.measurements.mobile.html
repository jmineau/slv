slv.measurements.mobile#

Mobile-platform measurements: the TRAX light-rail trains and the Wyoming mobile lab.

Submodules, one concern each:

  • network — TRAX lines, staged points, storage yards (JRRSC, MRSC), shed footprints, route-buffer filter.

  • gps — GPS readers (lin-group air-trend, horel-group CR1000 logger, era-based read_trax_gps()) and merge_with_gps().

  • location — per-minute location classifier: indoor (shed) vs outdoor (yard / pass-by / route / stopped), state / indoor / yard_name.

  • calibration — cal_source provenance and the uncalibrated windows.

  • obs — build_trax_obs() / load_trax_obs(), the cached CH4 record with both tag sets and a load-time location filter.

  • transects — transect matrices obs[transect, point]: the network builder (build_network_transects() / build_trax_transects() / load_network_transects()) and the archived per-line matrices (load_transects()).

  • receptors — STILT receptors: 50-m network points, 2-km segment crossings, one PYSTILT multipoint receptor per crossing, and dwell (parked-train) receptors.

  • receptor_obs — the CH4 observation for each of those receptors, keyed (obs_location, obs_time) exactly as the inversion joins them to the footprints.

  • wyoming — the Wyoming mobile lab (Aeris + met readers, enhancement ratios, wind-barb map); not re-exported, import from the module.

Every public function and table is re-exported here, so from slv.measurements.mobile import X works for all of them; the classifier thresholds (location) and GPS column/flag constants (gps) stay in their modules.

slv.measurements.mobile.assign_lines(point_lines, time_s, hit, window_s=1800.0, letters='RGBS')[source]#

The line letter each sample is on, resolved from the points around it in time.

point_lines is the lines string of each sample’s network point ("R", "BR", "BGR" on the trunk, …), time_s the sorted sample times (POSIX s) and hit whether the sample snapped to a point at all. Each sample is given the line, among the letters of its own point, with the most exclusive hits (samples on single-line points) within window_s before and after it. A sample on Red-only track is Red; a sample on the Red/Blue shared stretch is Red when the train was recently on Red-only track and Blue when it was recently on Blue-only track (e.g. a car in Blue service that just left the Blue-only stub at Salt Lake Central). The candidate restriction matters: a train that arrives from Green-only track and turns onto a Red/Blue-shared stretch must not carry G there, which a plain forward-fill did. Samples with no eligible vote (a point with no line tag, or half an hour on shared track with no exclusive point either side) come back "" and are left out of every line’s transits.

slv.measurements.mobile.build_dwell_receptors(fixes, dwells, freq='1h', min_minutes=30, altitude=4.0, altitude_ref='agl', hours=None, utc_offset=-7)[source]#

PYSTILT receptor table (RECEPTOR_COLUMNS) for the dwell periods.

One single-point receptor per freq bin of each dwell that holds at least min_minutes distinct minutes of data (counting minutes, not fixes, so the rule means the same thing in the 1-s and 10-s sampling eras), at the dwell’s median position, released at the median fix time inside the bin (rounded to the minute). A parked train is a stationary site, so the bin is an hour by default, exactly as the towers are treated; the release time follows the data rather than the bin edge because the train may only be there for part of it.

r_idx is dwell_<dwell>_<YYYYMMDDHH of the bin>, which receptor_obs parses back into a one-hour sample window, so freq must be exactly an hour: a shorter bin would give two receptors one r_idx, and a longer one would release the footprint at the median of the whole bin while the obs averages only its first hour.

hours restricts output to those local-time hours (see filter_receptor_hours()), e.g. range(12, 17) for the afternoon.

slv.measurements.mobile.build_trax_obs(site='trx01', time_range=None, num_processes=1, windows=None, classify=True, low_pressure=(100.0, 145.0), slope_tol=0.05, pressure_band=(135.0, 145.0), dropout_window=8, recover_hot=True, chunk='YS', **gps_kwargs)[source]#

Build the georeferenced TRAX CH4 record from the pipeline levels.

Sources, each tagged in cal_source (see CAL_SOURCES): lgr_ugga calibrated → pipeline; lgr_ugga_manual_cal qaqc → manual_cal; lgr_ugga qaqc inside the uncalibrated windows (default: the packaged table) → uncalibrated. QC via normalize_pollutant() (flags {0,1,2,-64,-140}, ID −10, valid range). Manual-cal rows flagged −63 (cavity pressure outside 135–145 torr) are kept when the pressure is inside low_pressure (default LOW_PRESSURE_BAND) and tagged low_pressure=True (apply_low_pressure_rule()); low_pressure=None drops them. Pipeline-calibrated rows whose slope deviates more than slope_tol from the day’s median slope are dropped (apply_slope_guard(); one bad reference period otherwise miscalibrates the next hour by 20–100 %). Then merged with every GPS fix by merge_with_gps() (no route buffer, no storage-yard removal) and, with classify, labelled per minute by label_trax_location() (state, indoor, yard_name) so that the location filter is applied at load time (load_trax_obs()). Pass routes / storage_polygon in gps_kwargs to restore the old pre-filtering.

The archive is processed in chunk-sized pieces (pandas offset alias, default one year) so that only one chunk of full-width pipeline files is in memory at a time (the whole-archive read peaked at 250 GB). Still heavy — run on a compute node.

slv.measurements.mobile.build_trax_receptors(crossings, points=None, min_coverage=0.5, min_span_m=0.0, max_duration='15min', altitude=4.0, altitude_ref='agl', time_round='1min', hours=None, utc_offset=-7)[source]#

PYSTILT receptor table (RECEPTOR_COLUMNS) from a crossings table.

One r_idx (= crossing) per crossing that drove at least min_coverage of its release geometry along the route (and at least min_span_m of it in metres, if set), with one row per 50-m point of the segment on the crossing’s line (release_points(); every such point, not only those with a fix, so a segment × line receptor geometry is always the same and its PYSTILT location id stable). time is the crossing’s median fix time rounded to time_round (UTC); crossings of one segment and line that round to the same minute are kept once. altitude is the roof inlet height in m AGL.

hours restricts output to those local-time hours (see filter_receptor_hours()). max_duration drops passes that are not traverses: at the five line termini the train dwells inside one segment between runs, so the pass can read 20 min or more and its median fix time is not the time it drove the track. None keeps them.

Build the [transect, point] matrix of one obs frame on the network points.

Parameters:

  • obs (DataFrame) – Georeferenced samples with Time_UTC, Longitude_deg, Latitude_deg and the species column (obs.parquet rows; cal_source and low_pressure are summarised per transit when present). Any order; sorted here.

  • points (GeoDataFrame) – load_trax_network_points() (any CRS; needs point, lines, segment and the s_<line> columns).

  • lag (float | DataFrame | None) – Inlet lag: None, seconds, or the per-epoch table with start/end/lag_s (inlet_lag_seconds()).

  • max_point_dist (float) – Snap radius to a network point [m]; farther samples are off-network.

  • max_gap (str | Timedelta) – A transit (and a run for the line assignment and lag) ends at a longer gap.

  • reversal_m (float) – lair.transects.split_transits(): turning-point prominence that ends a transit, and the shortest along-route span kept.

  • min_span_m (float) – lair.transects.split_transits(): turning-point prominence that ends a transit, and the shortest along-route span kept.

  • max_dwell_s (float | None) – lair.transects.transect_matrix(): samples at a point later than this after the transit first reached it are dropped (terminus dwells).

  • return_samples (bool) – Also return the per-sample assignment (Time_UTC, x, y lagged UTM position, point (-1 off-network), line ("" unresolved), transit (-1 not in a kept transit)), for diagnostics.

Returns:

dims transect x point; variables obs (ppm), time (mean POSIX s of the samples in the cell) and n (samples); point coords point (network id), lon, lat, lines, segment, s_<line>; transect coords line, direction (+1 with increasing s), heading (compass letter of travel), t_start, t_end, s_min, s_max, n_fix, n_points (points with data), coverage ((s_max - s_min) over that line’s full known extent – a short turn or a partial run reads well below 1; see the module docstring), lag_s, lag_source, and frac_uncalibrated / frac_low_pressure when the tags are present. Attributes record every parameter.

slv.measurements.mobile.classify_location(feat, moving_speed=2.0, moving_speed_est=1.5, line_distance=50.0, scatter_m=1.0, low_nsat=6, yard_buffer=30.0, near_yard_m=300.0, off_track_m=100.0, smooth_min=15, use_footprint=False)[source]#

Classify each row of location_features() into one of STATES.

Rules, per minute:

  1. no fixes → unknown

  2. moving (speed_max >= moving_speed, or where no speed was recorded speed_est >= moving_speed_est) on a track (d_track < line_distance): line if within near_yard_m of a storage polygon, else route; moving off-track inside the yard buffer → yard.

  3. stationary near the yard: degraded fix (scatter > scatter_m or nsat <= low_nsat, majority-voted over smooth_min minutes) → depot; with use_footprint a clean fix whose median sits inside the depot footprint is also depot. Off by default: the yard loop runs through the padded footprint, so it mislabels clean yard nights (e.g. 2025-02-16). Otherwise yard.

  4. stationary elsewhere → stopped.

  5. overrides to unknown: d_track > off_track_m (unless inside the yard buffer), or within near_yard_m of the storage polygon while neither on the line nor inside the yard buffer.

Returns a frame with state (categorical), indoor (nullable boolean: depot → True, other located states → False, unknown → NA), yard_name (copied from feat if present), degraded (raw per-minute flag), degraded_smooth and, when battery voltage is present, powered (volt_min >= POWER_OFF_V).

slv.measurements.mobile.find_segment_crossings(fixes, points=None, max_gap='10min', max_point_dist=60.0)[source]#

Split the GPS record into crossings of the 2-km segments.

Each fix is snapped to the nearest 50-m network point (dropped if farther than max_point_dist m) and inherits its segment; a crossing is a run of consecutive fixes on one segment with no gap longer than max_gap. One row per crossing:

crossing, segment, lines (letters common to every point hit — the line the train was on, in LINE_LETTERS order; "RGB" when only shared trunk points were hit), t_start, t_end, t_median, n_fix, n_points (distinct 50-m points hit), n_segment_points (points the segment has on that line), span_m, segment_extent_m and coverage.

span_m is measured along the route (the s_<line> coordinate of the points hit, from load_trax_network_points()), not as a straight line from the first fix: on a bent segment a full traverse can be 2.6 km of rail but only 1.8 km of chord, so a chord would make the same coverage look different on straight and bent segments. segment_extent_m is the along-route length of the release geometry (release_points()) and coverage = span_m / segment_extent_m is the fraction of it the train actually drove.

slv.measurements.mobile.read_horel_cr1000(time_range, site='trx01')[source]#

Horel-group CR1000 logger record (5 s): GPS + battery voltage + roof T/RH.

uataq raw level of the gps and cr1000 instruments (the monthly TRXnn_YYYY_MM_cr1000.h5 files), joined on time. The raw level is the one to use: the horel qaqc/final CSVs drop the satellite count and RMC status. Columns follow the uataq convention with N_Satellites renamed to N_Sat (Latitude_deg, Speed_m_s, N_Sat, Status, Battery_Voltage_V, Logger_T_C, Ambient_T_C, Ambient_RH_pct).

Indexed by GPS time, not the CR1000 clock (which runs 1-20 s ahead): see _to_gps_time(), which also adds Logger_Offset_s.

Covers Nov 2014 on (pilot files, then the post-pilot tree). The pilot-phase files (to HOREL_POST_PILOT) are a different setup: one fix per minute (so the scatter feature is undefined), a receiver that reports 3–8 satellites, and no speed or RMC status. Do not classify from them — use read_lin_gps() for the pilot era. time_range is any pair pandas can parse.

slv.measurements.mobile.read_trax_gps(time_range, site='trx01', fill_gaps=True)[source]#

Best GPS source for classifying, by era: lin-group GPS before HOREL_POST_PILOT, horel logger (with battery/T/RH) after.

With fill_gaps (default), minutes the horel logger did not record are filled from the lin GPS. The horel logger goes down for days at a time (its battery drained 2024-07-23 to 08-02; the logger was offline around 2025-09-02) and without this the classifier calls every such minute unknown — ~235 on-track hours of a normally running train, mostly Jul 2024, Jan 2025, Sep 2025 and Jul 2026. Filled rows carry no Battery_Voltage_V, so the depot/yard rules fall back to their GPS-only form.

slv.measurements.mobile.recover_hot_rows(cal, support, flag=-64)[source]#

Calibrate the rows the pipeline flagged -64 (cavity T outside 5-45 C) itself.

lgr_ugga_calibrate fits the slope for these rows (CH4d_m is there) but blanks CH4d_ppm_cal, so ~645 on-track hours of summer afternoons — the best-mixed hours of the record — never reach obs.parquet. The value is simply the qaqc reading over the fitted slope. Hot-cavity CH4 is unbiased: on the same days, the 10th percentile above 45 C differs from below by -0.002 ppm (IQR -0.008..+0.010, 65 days; measurements/trax/audit).

Returns the recovered rows (Time_UTC, CH4), which the caller appends to the calibrated ones.
